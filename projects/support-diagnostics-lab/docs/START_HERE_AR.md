# ابدأ هنا

الهدف أن تعرف لماذا تختار الفحص، وماذا تثبت نتيجته. ابدأ يدويًا ثم استخدم الأتمتة للمقارنة.

1. افتح طرفية في مجلد المشروع. شغّل `python lab/service.py --port 8765 --mode healthy` واتركها مفتوحة.
2. افتح طرفية ثانية واتبع [التجربة الأولى](MANUAL_PRACTICE_AR.md).
3. اكتب توقعك ثم النتيجة الفعلية وتفسيرها. اطلب مراجعة بعد المحاولة.
4. عند الانتهاء ارجع لطرفية الخدمة واضغط Ctrl+C؛ إغلاق المتصفح وحده لا يوقف الخدمة.

إذا لم يتعرف Windows على python أو pwsh، استخدم المسار الكامل للتطبيق المثبت. لا تنزّل أداة إضافية لمجرد تغيير اسم الأمر.

## تدريب Linux

إعداد WSL منفصل عن تشغيل المختبر. بعد الموافقة على الإعداد، افتح PowerShell بصلاحية المسؤول ونفّذ `wsl --install -d Ubuntu`. احفظ عملك قبل أي إعادة تشغيل مطلوبة؛ أعد التشغيل بنفسك عند استعدادك. عند أول فتح Ubuntu أنشئ اسم المستخدم وكلمة المرور مباشرة؛ لا ترسل كلمة المرور في المحادثة. قد لا تظهر أحرفها أثناء الكتابة.

مرجع الإعداد: [Microsoft WSL](https://learn.microsoft.com/en-us/windows/wsl/install).

بعد أن يظهر محث Ubuntu، نفّذ بنفسك:

```bash
uname -r
cat /etc/os-release
```

اشرح الفرق بين الناتجين. النواة داخل WSL تخص بيئة WSL؛ لا تساوي بالضرورة نواة جهاز Linux مادي تدعمه في العمل. عند التدريب على السجلات افحص أولًا وجود systemd ومدير الشبكة الفعلي. لا تفترض أن NetworkManager أو `/var/log/syslog` موجودان في كل نظام.

لا تُعتبر أمثلة الدليل تنفيذًا منك. سجّل ما نفذته فعلًا في قالب الحادث، واترك غير المنفذ واضحًا.
